## RAT для Windows (клиент-сервер).

Клиент подключается к серверу, получает команды, выполняет их, отправляет результаты

ПО для удаленного управления ПК (RAT). В качестве примера можно изучить такие проекты как Sliver, Merlin.
Программное обеспечение должно состоять из 3-х компонентов:
1.	Сервер управления
2.	 С2 -сервер
3.	Клиент

Сервер управления должен предоставлять:
1.	Интерфейс взаимодействия с пользователем (терминальный или веб интерфейс)
2.	Хранение и отображение истории команд в течении одной сессии взаимодействия
3.	Прием и передачу файлов с/на клиента с проверкой целостности
4.	Передачу команд командной строки клиенту с последующим получением и отображением результатов выполнения. (в том числе при возникновении ошибок передачи, обработки, выполнения команд)
5.	Шифрование отправляемых данных и дешифровку полученных ответов

C2-сервер должен предоставлять следующие возможности:
1.	Регистрацию клиентов
2.	Формирование списка клиентов
3.	Регистрацию задач для клиентов
4.	Сбор результатов выполнения задач от клиентов

Клиент должен предоставлять следующие возможности:
1.	Формирование и отправку регистрационного сообщения к заданному C2-серверу (ip и порт задаются при сборке)
2.	Периодический опрос C2-сервера на наличие новых задач
3.	Выполнение команд командной строки с перехватом стандартного потока вывода (STDOUT), а также стандартного потока вывода ошибок (STDERR).
4.	Доступ к файловой системе вычислительного устройства: чтение и запись объектов файловой системы. (при получении соответствующих задач необходимо проверять права доступа, существование файла. В случае возникновении проблем – генерировать соответствующее сообщение)
5.	Шифрование отправляемых данных и дешифровку полученных ответов

Общая схема функционирования: Есть клиент, C2-сервер и сервер управления. Команды от сервера управления передаются на C2, клиент забирает команды с C2, выполняет, кладет результаты на C2, сервер их оттуда читает и отображает.
Протокол общения сервера управления и C2-сервера – HTTP
Протокол общения клиента и C2-сервера - gRPC

ОС – Windows

Команды, которые необходимо выполнять:
-	команды командной строки;
-	загрузка файлов на клиент;
-	скачивание файлов с клиента.


В качестве языка разработки был выбран Golang.
Логика сборки прописана в Makefile. для быстрого старта:

```
make proto
make build-windows-n-hide
docker compose up --build -d
```

В результате Mgmt-сервер откроется на порту :8080, C2-сервер — :8081 для API и :50051 для gRPC.
